# M0.1: fixes, edge cases and a playful redesign

Follow-up to [M0](M0.md), requested after the owner hit errors running the app
and found the look bland.

## Bugs fixed

| Problem | Fix |
| --- | --- |
| A fresh clone failed with dozens of compile errors unless `build_runner` was run first | Generated code is now committed, and CI checks it stays current |
| Dart 3.13.3 SDKs could not resolve packages | SDK constraint relaxed to `^3.13.0` |
| The staff roster could only scroll one screen's worth, so staff beyond that were unreachable | Rebuilt with proper slivers; scrolling and loading the next page of 30 both work |
| A layout error (red screen) appeared while the roster was loading | The loading skeleton now sits in a sliver that allows scrolling content |
| Compact buttons (Invite staff, the gallery's colour buttons) stretched to full width | Buttons only fill the width when asked to |
| TalkBack could not activate buttons, tabs or cards | Every tappable component now exposes a semantic tap action |
| A bad or placeholder Supabase URL crashed the app on launch | Startup catches it; the welcome screen explains the problem |
| The member email link opened the browser, not the app | Android/iOS deep link registered; the router ignores auth callbacks |
| Unknown links showed the router's raw error page | A friendly "Lost your way?" page with a button home |
| Android back on any tab closed the app | Back returns to Home first |
| Status bar icons could be unreadable on screens without an app bar | The status bar style follows the theme everywhere |
| After a member PIN was set, the button stayed stuck on ✓ | Resets after 2 seconds, with confetti |
| Double-tapping Sign in, or pressing Enter, sent two requests | All forms ignore repeat submits while busy |
| Pasting "+91 98765 43210" into a phone field kept the wrong 10 digits | New formatter keeps exactly the local 10 digits |
| The `member-login` function minted the session on the admin client | Uses a separate throwaway client |
| A machine with less than 8 GB of RAM could fail Gradle start-up | Gradle heap lowered to 4 GB |
| Profile card overflowed at 1.3× text | Height is no longer fixed |

## Edge cases now handled

- **Offline start:** with a saved session, the app opens using the cached
  profile instead of an error screen.
- **Deactivated staff:**
  - The owner can turn access off and on from the Staff list.
  - A turned-off account is signed out and cannot sign in.
  - The owner account can't be turned off.
- **Clear messages for:**
  - Reused or weak passwords.
  - Too many attempts (rate limits).
  - An email that is already taken when inviting staff.
  - Actions the person isn't allowed to do.
- **Trainers** get their own home instead of the owner's setup checklist.

## Redesign: the "Pop" look

- **Palette:** six vivid hues, one per section, with ink text on every fill
  (AA contrast). Light mode is warm cream; dark mode is deep grape-night.
- **Shape:** sticker cards with bold outlines and hard "lips"; candy buttons
  that squish when pressed; pill stickers for statuses and roles.
- **Type:** Baloo 2 (playful, rounded, ₹ and tabular numbers) for headings and
  numbers, Nunito for body text.
- **Motion:** bouncy springs on tabs, nav icons, stickers and buttons; floating
  blobs; a wiggling waving hand in the greeting; confetti on success.
- **New and updated screens:**
  - Welcome: headline words on colour highlights, plus floating feature
    stickers.
  - Staff Home: a colourful "Get started" checklist.
  - Member Home: a gradient digital member card.
  - Onboarding: the colour changes as you swipe.
  - Floating tab bar.

## Tests added

12 new tests (92 Flutter tests in total, all passing). They cover:
- The phone formatter.
- Placeholder config.
- Auth error mapping.
- Turning staff off and on, and the owner lock.
- Long rosters with paging.
- Unknown links.
- Android back.
- Trainer home.
- The front-desk checklist.

Screenshots in `test/goldens/` were regenerated; the greeting date is pinned in
tests so the screenshots stay stable.

## Not verified here

This sandbox cannot reach Google's Android SDK servers, so the app was verified
by the analyzer, all tests, and a release **web** build running in Chromium,
but not by an Android build. The `main`-branch CI job builds the APK.
