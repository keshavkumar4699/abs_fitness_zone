# M0 Foundations: milestone report

Scope from the spec (§8): theme tokens, core components + Gallery screen, auth
for staff and members, router with role guards, CI, and the Supabase
foundations. Account and DNS setup (gym Gmail, Supabase dev/prod projects,
Cloudflare) are owner tasks; the README has the step-by-step checklist.

## Changelog

**App (Flutter 3.47.9, Android / iOS / web from one codebase)**
- Design tokens as code: colours (dark-first plus light, as a `ThemeExtension`),
  Sora/Inter type scale with tabular figures, the 4-pt spacing scale, radii,
  glass blur, and motion tokens (instant / quick / standard / expressive spring,
  40 ms stagger). Reduced motion is respected throughout.
- Core components in `lib/core/widgets/`: AbsButton (4 variants, press scale +
  haptic, width-preserving loading, success check), AbsCard, StatTile
  (count-up, delta pill, sparkline), MemberTile (status ring, swipe right to
  collect, swipe left to remind, haptic at threshold), StatusPill, ProgressRing
  (draws in once), AbsTextField (validates on blur, ₹ / +91 prefixes),
  SegmentedTabs, AbsBottomSheet (snaps at 50% / 92%), EmptyState (original line
  illustrations), ErrorState, SkeletonList, AbsSnackbar (with Undo),
  SearchBarHero (large title collapsing into a sticky glass search),
  ChartCard (line/bar, draw-in, tooltips, 7D/30D/3M/12M), QuickActionFab,
  AsyncView (loading / empty / error / data with a 200 ms cross-fade), list
  entrance stagger, and accent pull-to-refresh.
- Hidden **Component gallery** showing every component and state, with
  light/dark and 1.3× text toggles.
- Auth:
  - Staff sign in with email and password; a forced new password on first
    sign-in.
  - Members sign in with phone and a 4-digit PIN, with a lockout message
    showing attempts left and the unlock time. "Forgot PIN" points them to the
    front desk, and there is an email magic-link fallback.
  - First-run member onboarding: 3 parallax cards.
- Router with role guards: signed-out, staff and member areas; owner-only and
  owner/front-desk-only pages; deep links bounce to an allowed page.
- Adaptive shells: bottom navigation with glass blur on phones, a navigation
  rail on tablets, and a collapsible side nav with a Ctrl/⌘+K command palette on
  desktop web. Tabs fade-through; flows use shared-axis transitions.
- **More** (staff):
  - Profile and role, and an Appearance setting (System / Light / Dark, saved).
  - **Staff** (owner): searchable, paginated roster with pull-to-refresh and an
    invite sheet that issues a one-time temporary password.
  - **Member PIN** (owner, front desk): look up a member by phone and set their
    PIN.
- Member **Profile**: member ID, phone, appearance, sign out.
- Utilities: money in integer paise with ₹ Indian grouping, IST date maths and
  formatting, +91 phone normalisation.
- Localisation layer (`app_en.arb`; `app_hi.arb` is ready for Hindi with no
  code changes). Sentry crash reporting is wired in and turned on by
  `SENTRY_DSN`.

**Backend (Supabase)**
- Migration `20261102000000_m0_foundations.sql`:
  - Tables: `staff`, `members` (core record with auto `ABS-0001` codes,
    trigram name index and phone prefix index), `profiles` (role per auth
    user), `member_credentials`, `member_login_attempts`, `settings`,
    `audit_log` plus a generic audit trigger.
  - Helpers: `auth_role()`, `auth_member_id()`, `auth_staff_id()`,
    `is_owner()`, `is_desk()`, `is_staff()`.
  - RLS on every table.
  - RPCs: `public_gym_profile`, `mark_password_set`, `set_member_pin`,
    `verify_member_pin` (service role only), `bootstrap_owner`.
- Edge Functions: `member-login`, `set-member-pin`, `invite-staff`, with shared
  input validation.

**Delivery**
- GitHub Actions:
  - CI: format, analyze, all tests, Deno check and tests, migrations + RLS
    tests on Postgres 16.
  - Release on tag: APK, AAB and web build, a GitHub release with the APK, and
    Cloudflare Pages and Supabase deploys when their secrets are set.
  - Nightly backup to Google Drive, plus a 6-hourly keep-alive ping.
- Release signing from `android/key.properties` when present; falls back to the
  debug key otherwise.

## Not yet verified

- **On-device Android profiling.** The 60 fps / no-jank check in profile mode
  on a mid-range phone needs a physical device. Run
  `flutter run --profile --dart-define-from-file=env/dev.json` before sign-off.
- **Against a live Supabase project.** The Edge Functions are type-checked and
  their validation is unit-tested, and the SQL runs against Postgres 16 with a
  stubbed `auth` schema. The end-to-end member PIN login (the magic-link
  minting step) needs a real project to confirm.
